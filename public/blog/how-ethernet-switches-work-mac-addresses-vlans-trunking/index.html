How Ethernet Switches Work: MAC Addresses, Frames, VLANs and Trunking

Understand how Ethernet switches learn MAC addresses, forward frames, separate networks with VLANs, use 802.1Q trunks and prevent switching loops.

By Suraj Vishwakarma · Published by TEZZ CONNECT

An Ethernet switch connects devices inside a local area network and sends each Ethernet frame toward the correct destination. It does this by learning which Media Access Control (MAC) addresses are reachable through which ports. Instead of sending every frame to every connected device, a switch can usually forward known unicast traffic only where it needs to go.

That simple job is the foundation of wired office networks, home networks, data-centre fabrics, campus networks and the wired connections used by Wi-Fi access points. Modern switches also support features such as Virtual LANs (VLANs), link aggregation, traffic prioritisation, loop prevention, monitoring and sometimes IP routing.

To understand a switch, it helps to follow a frame through the device. The switch receives an electrical or optical signal, reconstructs an Ethernet frame, checks its fields, learns the source address, consults its forwarding information and decides whether to forward, filter or flood the frame. VLAN membership determines which logical network the frame belongs to. Trunk links can carry several VLANs between switches using tags, while Spanning Tree Protocol helps prevent loops in redundant topologies.

This guide explains those ideas from first principles. It is written for home-network owners, students, IT support teams and anyone planning a small office or campus network. It also explains why a switch is not the same thing as a router, why a faster switch does not automatically increase internet speed, and which specifications matter when choosing equipment.

1. What is an Ethernet switch?

An Ethernet switch is a network device that connects multiple wired endpoints and forwards Ethernet frames between them. Endpoints may include computers, printers, servers, network-attached storage, routers, wireless access points, IP cameras and other Ethernet-enabled equipment.

Each physical port is a connection point. When a device sends data, its network interface places the information inside an Ethernet frame and transmits it over the cable or fibre. The switch receives the frame on one port and determines which other port or ports should receive it. In a typical switched full-duplex Ethernet network, devices can transmit and receive simultaneously without competing for a shared collision domain in the way older hub-based Ethernet did.

A switch is primarily a Layer 2 device in the OSI model. Layer 2 is the data-link layer, where Ethernet frames and MAC addresses are used for delivery across a local network segment. Many switches also include Layer 3 capabilities, which allow them to route IP traffic between VLANs. Those devices are commonly called Layer 3 or multilayer switches.

The word “switch” can describe products with very different capabilities. An unmanaged desktop switch may simply forward frames. A managed enterprise switch may support VLAN configuration, access control, spanning tree, link aggregation, quality of service, monitoring and routing. Always check the actual feature set rather than assuming that every device with several Ethernet ports supports the same functions.

2. What is an Ethernet frame?

Ethernet transports data in units called frames. A frame contains addressing and control information around the payload being carried. In a common Ethernet II frame, the header includes a destination MAC address, a source MAC address and an EtherType field that identifies the upper-layer protocol carried in the payload. The frame ends with a Frame Check Sequence (FCS) used for error detection.

The destination MAC address identifies the intended receiver on the local Ethernet link. The source MAC address identifies the sender's network interface. The EtherType commonly identifies protocols such as IPv4, IPv6 or ARP. The payload may contain an IP packet, but Ethernet itself does not need to understand the full application conversation inside that packet to perform ordinary Layer 2 forwarding.

The FCS is based on a cyclic redundancy check. It helps a receiver detect corruption in a frame during transmission. A switch normally discards frames that fail its frame check rather than forwarding corrupted data as if it were valid. The FCS is not an encryption mechanism and does not prove who sent the frame; it is an error-detection field.

Ethernet frames also have size limits. Traditional Ethernet supports a standard maximum payload of 1,500 bytes, while the frame itself includes additional header and trailer fields. Jumbo frames are supported by some equipment but are not universally enabled or interoperable. Every device along a path must support a compatible frame size if jumbo frames are used end to end.

A VLAN-tagged frame carries an additional four-byte IEEE 802.1Q tag. That tag is inserted after the source MAC address and before the original EtherType/Length field. The tag identifies the VLAN and carries priority information. The frame check sequence is recalculated to cover the transmitted frame.

3. What is a MAC address?

A Media Access Control address is a link-layer identifier used by Ethernet interfaces. A conventional Ethernet MAC address is 48 bits long and is usually written as six hexadecimal octets, such as 00:1A:2B:3C:4D:5E. The address appears in the source and destination fields of Ethernet frames.

MAC addresses are associated with network interfaces, not with a person's identity or a permanent location. A laptop may have separate MAC addresses for its Ethernet and Wi-Fi interfaces. Virtual machines, containers and software-defined networks can also use virtual MAC addresses. Some operating systems use per-network MAC address randomisation for privacy on Wi-Fi.

The first part of a globally administered MAC address can identify an organisationally assigned block, but this should not be treated as a reliable identity check. Addresses can be locally administered or changed by software. A MAC address is useful for local frame delivery, but it is not a substitute for authentication or encryption.

MAC addressing is different from IP addressing. A MAC address is used for delivery on a local Layer 2 network, while an IP address identifies a logical interface within an IP network and supports routing between networks. When a computer sends an IP packet to a destination on its local subnet, it needs the destination device's MAC address. When the destination is on another IP network, the computer normally sends the Ethernet frame to the MAC address of its default gateway instead.

4. How does a switch learn MAC addresses?

A switch builds a forwarding database by examining the source MAC address of incoming frames. Suppose a computer connected to port 3 sends a frame. The switch records that the source MAC address was seen on port 3, within the frame's VLAN. If another frame from the same address arrives later on the same port, the switch refreshes the entry's age or timer.

This process is called MAC learning. The switch does not need an administrator to type in every computer's address for ordinary dynamic forwarding. As devices communicate, the switch learns which addresses are reachable through each port. Entries are maintained per VLAN because the same MAC address can theoretically appear in different VLAN contexts.

When the switch receives a frame, it looks up the destination MAC address in the forwarding database. If the address is known and the outgoing port is eligible, the switch forwards the frame toward that port. If the destination is on the same port where the frame arrived, the switch can filter it rather than sending it back out the same interface.

Dynamic entries are generally aged out when no frames are seen from the address for a configured period. This is useful when a device moves to another port or disconnects. If the device starts transmitting from a new port, the switch can learn the new location and update the table. Static MAC entries can also be configured in some environments, but they require maintenance and are not needed for most ordinary endpoints.

MAC learning is local to the switching domain. A switch does not learn the MAC address of a remote internet server merely because a user opens a website. It learns the local next-hop MAC address, often the router or gateway, that receives the computer's Ethernet frame.

5. How does a switch forward, filter and flood frames?

After learning the source address, the switch examines the destination address and makes a forwarding decision. Three common outcomes explain most Layer 2 behaviour:

  • Known unicast: the destination MAC is present in the forwarding database. The frame is sent toward the associated port, subject to VLAN and port-state rules.
  • Unknown unicast: the destination is not in the forwarding database. The switch usually floods the frame to eligible forwarding ports in the same VLAN, excluding the incoming port.
  • Broadcast: the destination is the Ethernet broadcast address. The frame is flooded to eligible ports in the same VLAN, excluding the incoming port.

Multicast forwarding has additional considerations. A basic switch may flood some multicast traffic within a VLAN. A switch that supports Internet Group Management Protocol (IGMP) snooping can observe membership reports and constrain certain IPv4 multicast streams to ports that have requested them. IPv6 uses Multicast Listener Discovery (MLD) for related membership functions. Correct operation depends on the network's multicast design and configuration.

Flooding is not necessarily a fault. When a device is first contacted, the switch may not yet know its location. Flooding allows the frame to reach the intended endpoint, which can reply. The reply's source MAC address teaches the switch where that endpoint is. Future known unicast frames can then be forwarded more selectively.

VLAN boundaries limit the scope of flooding. A broadcast in one VLAN is not normally forwarded into another VLAN by a Layer 2 switch. This is one reason VLANs are used to divide large networks into smaller broadcast domains.

6. Switch vs hub vs router: what is the difference?

A hub is a basic multiport repeater. It repeats incoming electrical signals to other ports rather than learning destination MAC addresses and selectively forwarding frames. All connected devices share the same collision domain, and a hub does not create the separate point-to-point forwarding behaviour of a modern Ethernet switch. Hubs are now largely obsolete in ordinary networks.

A Layer 2 switch learns MAC addresses and forwards frames within a VLAN. Each switch port creates a separate collision domain, and modern full-duplex links do not use Ethernet collision detection in the old shared-medium way. The switch can connect many devices while limiting unnecessary traffic to the relevant ports.

A router connects different IP networks. It examines the destination IP address and consults a routing table to decide the next hop. When a packet travels from a home LAN to the internet, the router sends it toward the ISP using the route for the destination. A router may also perform Network Address Translation, firewall filtering, DHCP and other services, depending on the product.

A Layer 3 switch combines high-speed Layer 2 switching with IP routing functions. It can route between VLANs locally using switched virtual interfaces or routed ports. This is common in campus networks where many VLANs need to communicate through controlled Layer 3 boundaries.

A home broadband router often includes a small Ethernet switch, Wi-Fi access point, routing functions, firewall and sometimes modem or optical network termination features in one box. That combination can make the distinction less obvious, but the functions remain different.

7. What is a VLAN?

A Virtual Local Area Network (VLAN) is a logical Layer 2 network. It allows a physical switching infrastructure to carry several separate broadcast domains. Devices assigned to one VLAN can exchange Layer 2 frames within that VLAN, while devices in another VLAN remain separate unless a Layer 3 device routes traffic between them.

Imagine a small office with staff computers, guest Wi-Fi, IP cameras and network printers. Without VLAN separation, all devices may share the same Layer 2 broadcast domain. With VLANs, the organisation can place staff devices in one VLAN, guests in another, cameras in a third and infrastructure management in a fourth. The same physical switch may carry these networks, but forwarding rules keep their Layer 2 traffic separate.

VLANs can reduce unnecessary broadcast traffic and help organise network policy. They are also useful for applying different firewall rules, access controls, DHCP scopes and monitoring. A guest VLAN can be routed to the internet while being denied access to internal servers. A camera VLAN can be allowed to communicate with a video recorder but not with employee laptops.

A VLAN is not automatically a firewall or a complete security boundary. A device with permission to route between VLANs can connect them. Misconfigured trunks, overly broad routing rules or compromised network equipment can undermine intended separation. VLAN design should be paired with Layer 3 access controls, firewall policy, secure management and monitoring.

8. What is an IEEE 802.1Q VLAN tag?

IEEE 802.1Q defines a standard method for identifying VLAN membership in Ethernet frames. The tag adds four bytes to the frame. It contains a Tag Protocol Identifier (commonly 0x8100) and Tag Control Information. The control information includes a 12-bit VLAN Identifier (VID), priority bits and a drop-eligibility bit.

A 12-bit VLAN identifier provides 4,096 possible values in the field. Some values are reserved for special purposes, so the number of ordinary VLAN IDs available for assignment is lower than the raw mathematical total. The VLAN ID tells a receiving switch which logical network the tagged frame belongs to.

The priority field is associated with traffic class handling. It can be used with Quality of Service policies to help distinguish traffic such as voice or other delay-sensitive services. A priority value does not guarantee bandwidth or end-to-end quality by itself; every relevant device and queue along the path must be configured appropriately.

When a frame travels across a trunk, switches use the VLAN tag to preserve its VLAN identity. When the frame leaves through an access port for an ordinary endpoint, the switch typically sends it untagged because most computers and printers are not configured to process tagged frames. Some servers, hypervisors and specialised endpoints can handle tagged VLAN traffic directly.

9. Access ports and trunk ports

An access port is normally assigned to one VLAN. It is commonly used for an end device such as a desktop computer, printer, camera or ordinary server interface. Frames arriving untagged on the access port are associated with the configured access VLAN. The switch generally transmits frames to the endpoint without a VLAN tag.

A trunk port carries traffic for multiple VLANs across one physical link. Trunks are commonly used between switches, between a switch and a router, or between a switch and a server or hypervisor that needs multiple VLANs. IEEE 802.1Q tagging allows the receiving device to distinguish traffic belonging to each VLAN.

Trunks should be configured deliberately. An allowed-VLAN list limits which VLANs may cross the link. A native VLAN setting determines how untagged traffic is handled on many implementations. Both ends of a trunk should have compatible settings. A native VLAN mismatch can lead to unexpected forwarding or security problems.

Do not leave unnecessary VLANs enabled on every trunk. Restricting the allowed list reduces accidental exposure and makes troubleshooting easier. Disable unused ports or place them in an isolated unused VLAN according to the organisation's policy. Avoid connecting untrusted devices to a trunk because a trunk may provide access to multiple logical networks.

10. How does traffic move between VLANs?

Ordinary Layer 2 switching does not route traffic between different VLANs. Each VLAN is a separate broadcast domain. If a computer in VLAN 10 needs to communicate with a server in VLAN 20, the IP packet must be routed by a router or Layer 3 switch.

In a router-on-a-stick design, a router connects to a switch through a trunk. The router uses logical subinterfaces, each associated with a VLAN tag and IP subnet. It receives traffic from one VLAN, makes an IP routing decision and sends the packet back out with the destination VLAN's Layer 2 encapsulation. This design can be suitable for smaller networks but may concentrate traffic on a single physical link.

A Layer 3 switch can create a switched virtual interface (SVI) for each VLAN. The SVI acts as the IP gateway for devices in that VLAN. The switch routes packets between the VLAN interfaces using its routing functions. Access control lists or other security policy can restrict which VLANs may communicate.

For example, staff VLAN 10 might use subnet 192.0.2.0/24 and guest VLAN 20 might use 198.51.100.0/24 in a documentation example. The Layer 3 gateway can route guest traffic to the internet while blocking access to staff devices. The example addresses are reserved for documentation and should not be copied as live public network assignments.

11. Why do Ethernet networks need Spanning Tree Protocol?

Redundant links improve resilience, but they can create Layer 2 loops. Imagine two switches connected by two active links, with broadcast traffic entering the network. Without a loop-prevention mechanism, a frame can circulate repeatedly because Ethernet frames do not include a general hop-count field that automatically expires after a number of switches.

Broadcast storms can consume link capacity and switch processing resources. MAC address tables may also become unstable as the same source address appears to move between ports. The result can be severe network disruption, even when the original amount of traffic was small.

Spanning Tree Protocol (STP) helps create a loop-free logical topology. Switches exchange Bridge Protocol Data Units (BPDUs), elect a root bridge and calculate which ports should forward traffic and which redundant paths should be placed into a non-forwarding state. If an active path fails, the topology can reconverge and a previously blocked path may become available.

There are several spanning-tree variants, including classic STP, Rapid Spanning Tree Protocol (RSTP) and Multiple Spanning Tree Protocol (MSTP). Implementations differ in convergence behaviour and how they handle VLANs or groups of VLANs. Use a consistent design and configure edge-port protections, BPDU Guard or equivalent safeguards where appropriate to prevent an end device from accidentally or maliciously becoming part of the switching topology.

12. Link aggregation: combining multiple links

Link aggregation combines multiple physical Ethernet links into one logical connection. It can increase the aggregate capacity available across multiple traffic flows and provide resilience if one member link fails. IEEE 802.1AX defines link aggregation, and Link Aggregation Control Protocol (LACP) is commonly used to negotiate and maintain an aggregation between compatible devices.

Aggregation does not usually make one individual data flow run at the sum of all link speeds. Switches commonly distribute flows using a hash based on fields such as source and destination MAC addresses, IP addresses or transport ports. A single flow may remain on one member link to preserve packet ordering, while multiple independent flows can use different links.

Both ends must be configured consistently. The links should have compatible speeds and settings, and the devices must support the same aggregation mode. A mismatch can cause links to remain inactive or create unexpected forwarding. Link aggregation is not a substitute for a properly sized uplink or a routed network design.

13. Managed vs unmanaged switches

An unmanaged switch is designed for straightforward connectivity. It usually works as soon as power and Ethernet cables are connected. It may be suitable for a home office, small lab or simple extension where VLANs, detailed monitoring and advanced controls are not required.

A managed switch provides a configuration interface, commonly through a web interface, command-line interface, network controller or management protocol. Features may include VLANs, trunking, port security, spanning tree, link aggregation, QoS, port mirroring, SNMP, logging and firmware management. The exact features vary by model and software licence.

Smart or web-managed switches sit between basic unmanaged and full enterprise models. They may offer common VLAN and monitoring functions without the complete feature set of a high-end managed switch. For a small business, this can be a useful balance, but confirm that the switch supports the specific features the network needs.

Management adds responsibility. Change default credentials, restrict management access to a trusted VLAN, use secure management protocols, keep firmware updated and maintain configuration backups. A managed switch can improve visibility and control, but a poorly secured management plane can become a significant risk.

14. Switch speed, capacity and buying considerations

Port speed is one of the first specifications people notice: Fast Ethernet (100 Mb/s), Gigabit Ethernet (1 Gb/s), 2.5 Gigabit Ethernet, 5 Gigabit Ethernet and 10 Gigabit Ethernet are common examples. Choose port speeds based on endpoint capability, server traffic, Wi-Fi access point uplinks and expected growth.

Switching capacity or fabric bandwidth describes the aggregate amount of traffic the switch can process across its ports under specified conditions. Forwarding rate describes how many packets or frames it can process per second. These figures should be considered alongside the number of ports and the duplex assumptions used by the manufacturer. A switch with high port speeds but inadequate internal capacity may oversubscribe under heavy simultaneous traffic.

Uplink ports matter. A switch with many gigabit access ports but only one gigabit uplink may create a bottleneck when many devices communicate with a central server or router. A 10 Gb/s uplink, multiple uplinks or link aggregation may be appropriate depending on traffic patterns. The right design depends on where data flows, not just the largest number printed on the product box.

Also check PoE support if the switch will power access points, cameras or phones. Verify the IEEE PoE type, per-port output and total power budget. Our separate guide to Power over Ethernet standards and power budgets explains those requirements. For cabling, see Ethernet cable categories and their practical limits.

Other considerations include fan noise, rack mounting, operating temperature, power supply redundancy, warranty, software support, security features and the ability to monitor faults. In a home, a silent fanless switch may be preferable. In a data centre or campus distribution layer, redundancy and monitoring may be more important.

15. Common Ethernet switching problems

A device cannot communicate with another device on the same network. Check link status, cable termination, speed and duplex negotiation, VLAN assignment, MAC learning and endpoint IP configuration. Confirm that both devices are in the intended VLAN and that no port security or access policy is blocking traffic.

A device receives an IP address from the wrong network. This can happen when an access port is assigned to the wrong VLAN, when a trunk carries an unintended VLAN, or when DHCP services are reachable from an unexpected segment. Verify the port's VLAN membership, trunk allowed list, native VLAN and DHCP relay configuration.

Intermittent connectivity appears after adding a second switch link. A Layer 2 loop or spanning-tree issue may be present. Check STP topology changes, root bridge selection, blocked ports and link aggregation configuration. Never connect redundant links casually without understanding the loop-prevention design.

One switch uplink is saturated. Examine traffic patterns, uplink speed, oversubscription and whether link aggregation or a faster uplink is supported. Check for large backups, camera streams, multicast traffic or server transfers. A higher-speed internet plan will not resolve a congested internal switch uplink.

Wireless users are slow but wired users are fine. The switch may be operating normally while the access point, radio environment, channel selection or wireless uplink is the limiting factor. Check access point port speed, PoE capability, VLAN mapping and wireless performance separately.

MAC addresses appear to move between ports. This may be normal when a device moves, but repeated unexpected movement can indicate a loop, redundant connection, virtualisation configuration or an unintended topology. Check cabling, aggregation and virtual switch settings.

16. A simple small-office VLAN design

Consider a small office with employee computers, guest Wi-Fi, cameras and network management. A practical design could use separate VLANs for each function, with IP subnets and Layer 3 policies matched to the organisation's needs. The exact VLAN IDs are local choices; the important part is documenting them consistently.

  • VLAN 10 — Staff: employee laptops, desktops and approved printers.
  • VLAN 20 — Guest: visitor wireless clients with internet-only access.
  • VLAN 30 — Cameras: IP cameras and the video recorder, with limited permitted communication.
  • VLAN 99 — Management: switch and access-point management interfaces, accessible only to authorised administrators.

Access ports connect ordinary endpoints to the correct VLAN. Trunk links connect switches and carry only the VLANs required at each location. A router or Layer 3 switch provides gateways and enforces traffic rules. Guest devices should not be able to reach staff computers or management interfaces merely because they share the same physical switch.

Document which ports connect to which rooms and devices. Label cables, save switch configurations, monitor logs and review access policy when devices or staff change. A simple documented network is easier to troubleshoot and secure than a complex design that exists only in one administrator's memory.

17. Does an Ethernet switch improve internet speed?

A switch can improve local network performance if the existing network is constrained by an old hub, a slow port, a congested uplink or a faulty device. Replacing a 100 Mb/s bottleneck with a gigabit connection can help compatible devices exchange data faster within the LAN. A faster uplink can also help when multiple computers access a local server or network storage.

However, a switch does not increase the bandwidth purchased from an internet service provider. If the broadband connection is 100 Mb/s, replacing a gigabit switch with a 10 Gb/s model does not turn the ISP service into a 10 Gb/s connection. The internet path may be limited by the ISP plan, router, modem or ONT, Wi-Fi, remote server, congestion or the endpoint itself.

Use a wired speed test to isolate the issue. Connect a capable computer directly to the router or switch with a known-good cable, confirm negotiated link speed, and compare local and internet performance. If local file transfers are fast but internet tests are slow, investigate the WAN connection and ISP. If local transfers are slow too, examine switch ports, cabling, NIC settings, storage performance and uplink capacity.

18. Practical Ethernet switch checklist

  • Count endpoints and choose enough access ports with room for expansion.
  • Match port speeds to computers, servers, access points and uplink requirements.
  • Check switching capacity and forwarding rate for expected simultaneous traffic.
  • Decide whether VLANs, trunks, management and monitoring are needed.
  • Plan Layer 3 routing and firewall policy for communication between VLANs.
  • Configure trunk allowed-VLAN lists and compatible native VLAN settings.
  • Enable an appropriate spanning-tree mode before adding redundant Layer 2 links.
  • Check PoE type and total power budget if the switch powers endpoints.
  • Secure management interfaces, update firmware and back up configurations.
  • Label ports and cables, document VLANs and monitor link and error counters.

Conclusion: switches make Ethernet networks organised and scalable

An Ethernet switch is more than a box that adds network sockets. It learns source MAC addresses, builds a forwarding table, forwards known unicast frames, floods unknown destinations and broadcasts within the correct VLAN, and filters traffic that does not need to leave its incoming port.

VLANs extend that foundation by dividing one physical switching infrastructure into separate logical networks. IEEE 802.1Q tags preserve VLAN identity across trunk links, while routers and Layer 3 switches provide controlled communication between VLANs. Spanning Tree Protocol protects redundant Layer 2 designs from loops, and link aggregation can combine physical links for capacity and resilience.

When choosing or troubleshooting a switch, look beyond the port count. Consider speed, uplink capacity, VLAN support, management, security, PoE requirements and the network's traffic patterns. A correctly designed switch network makes local communication more efficient, easier to manage and safer to expand.

Frequently asked questions about Ethernet switches

1. What does an Ethernet switch do?

An Ethernet switch connects devices in a local area network and forwards Ethernet frames toward the port associated with the destination MAC address. It learns source MAC addresses to build a forwarding table and keeps traffic within the appropriate VLAN.

2. How does a switch learn MAC addresses?

A switch examines the source MAC address of each incoming Ethernet frame and records the address with the VLAN and ingress port. It refreshes entries as traffic arrives and ages out entries that have not been seen for a configured period.

3. What happens when a switch does not know the destination MAC address?

For an ordinary unknown unicast frame, the switch generally floods it to eligible forwarding ports in the same VLAN, except the port on which it arrived. When the destination replies, the switch can learn its source MAC address and forward later frames selectively.

4. What is the difference between a switch and a router?

A Layer 2 switch forwards Ethernet frames using MAC addresses within a LAN or VLAN. A router forwards IP packets between different IP networks using routing information. A Layer 3 switch can perform both switching and routing functions.

5. What is a VLAN in simple terms?

A Virtual LAN is a logical Layer 2 network that separates devices into distinct broadcast domains even when they share physical switching infrastructure. Devices in different VLANs normally need a router or Layer 3 switch to communicate.

6. What is the difference between an access port and a trunk port?

An access port normally carries traffic for one assigned VLAN and connects end devices. A trunk port carries traffic for multiple VLANs between network devices, commonly using IEEE 802.1Q tags to identify each frame's VLAN.

7. What is an 802.1Q VLAN tag?

IEEE 802.1Q adds a four-byte tag to an Ethernet frame. The tag includes a 12-bit VLAN identifier and priority information, allowing switches to keep frames associated with the correct VLAN across trunk links.

8. Can devices in different VLANs communicate?

Not through ordinary Layer 2 switching alone. Communication between VLANs requires Layer 3 routing, such as a router-on-a-stick design or a Layer 3 switch with VLAN interfaces and appropriate routing and security rules.

9. Why is Spanning Tree Protocol needed?

Redundant Layer 2 links can create loops that cause frames to circulate, multiply and overwhelm a network. Spanning Tree Protocol identifies redundant paths and places selected ports into a non-forwarding state to maintain a loop-free topology while preserving backup links.

10. Does a faster Ethernet switch make internet faster?

Not necessarily. A switch can remove a local bottleneck if its ports or uplinks were limiting traffic, but it cannot increase the speed supplied by an ISP or fix Wi-Fi, router, server or congestion problems elsewhere.
