How ARP Works: IP-to-MAC Address Resolution, ARP Cache and Spoofing

Understand how Address Resolution Protocol maps IPv4 addresses to Ethernet MAC addresses, how ARP requests and replies work, how caches and gateways behave, and how to troubleshoot spoofing.

By Suraj Vishwakarma · Published by TEZZ CONNECT

ARP (Address Resolution Protocol) connects IPv4 addressing to local Ethernet delivery. When a device needs to send an IPv4 packet over an Ethernet network, it must know the MAC address of the local destination or next-hop router. ARP discovers that mapping and stores it so future packets can be sent efficiently.

This guide explains the complete process, from ARP request and reply to cache ageing, gateway resolution, gratuitous ARP, proxy ARP and spoofing. It also shows how ARP fits with switches, routers, VLANs and IPv6 Neighbor Discovery.

1. What is ARP?

Address Resolution Protocol (ARP) helps an IPv4 device discover the link-layer address needed to deliver a packet on a local network. An application may know the destination's IP address, but an Ethernet frame needs a destination MAC address. ARP provides the mapping between an IPv4 address and a hardware address on the local link.

ARP is defined in RFC 826. It is commonly associated with Ethernet and IPv4 LANs. It does not replace IP routing, assign IP addresses or discover a remote server's MAC address across the internet. It resolves the next-hop address on the local network.

This distinction explains a common networking question: when a laptop connects to a website hosted on another network, it normally does not ARP for the website's public IP. It ARPs for the MAC address of its default gateway, then sends an Ethernet frame to the router. The router handles the next network hop.

ARP is a small protocol, but it is central to everyday IPv4 communication. When its mappings are missing, stale or maliciously changed, devices may experience connection delays, intermittent reachability or traffic interception.

2. Why IP addresses and MAC addresses are both needed

IP and MAC addresses serve different purposes. An IPv4 address identifies an interface at the network layer and supports routing between IP networks. An Ethernet MAC address identifies a network interface on a local Layer 2 segment. A packet can travel through several routers while its IP source and destination remain the same end-to-end in ordinary forwarding, but the Ethernet source and destination addresses are rewritten for each routed link.

Think of an IP address as the logical destination used to decide where a packet should go, and a MAC address as the local delivery label used on the current Ethernet segment. The analogy is not exact, but it helps separate routing from local frame delivery.

A host first uses its subnet mask or prefix length to determine whether the destination IPv4 address is on the same local subnet. If it is local, the host resolves the destination's MAC address. If it is remote, the host selects a router using its routing table and resolves the MAC address of that next-hop router.

ARP therefore works alongside the routing table. It does not decide the route. The routing decision determines which local interface and next-hop IP address require link-layer resolution.

3. How an ARP request works step by step

Suppose a laptop has IPv4 address 192.168.1.20/24 and wants to contact a printer at 192.168.1.50 on the same subnet. The laptop checks its ARP cache. If it has no usable mapping for 192.168.1.50, it sends an ARP Request.

  1. The laptop prepares an ARP message identifying the sender's protocol address and hardware address, and the target protocol address it wants to resolve.
  2. The request is carried in an Ethernet frame addressed to the broadcast MAC address FF:FF:FF:FF:FF:FF.
  3. Switches in the same Layer 2 broadcast domain flood the broadcast frame out eligible ports, except the port on which it arrived.
  4. Devices receive the request and inspect the target IPv4 address. The printer recognises its own address.
  5. The printer sends an ARP Reply containing its MAC address. A normal reply is usually unicast to the requester.
  6. The laptop records the mapping in its ARP cache and can send the IP packet inside an Ethernet frame addressed to the printer.

The request is a broadcast because the sender does not yet know which interface owns the target IPv4 address. The reply can be unicast because it identifies the requester. Implementations may also learn useful sender mappings from received ARP packets, subject to operating-system rules and security settings.

ARP is local to a Layer 2 broadcast domain. Routers do not forward ordinary Ethernet broadcasts between IP subnets. That is why a host on one subnet resolves its gateway rather than broadcasting an ARP request across the internet for a remote destination.

4. What is inside an ARP packet?

RFC 826 defines fields that describe the hardware address type, protocol address type, address lengths, operation and sender/target addresses. For common Ethernet with IPv4, the hardware type identifies Ethernet, the protocol type identifies IPv4, the hardware address length is six bytes and the protocol address length is four bytes.

The operation field identifies a request or reply. In common ARP usage, operation 1 means request and operation 2 means reply. The sender hardware address and sender protocol address identify the sender. The target protocol address identifies the IPv4 address being resolved. The target hardware address may be unknown in a request.

Packet captures commonly show these fields in a human-readable form: “Who has 192.168.1.50? Tell 192.168.1.20.” The reply reads approximately: “192.168.1.50 is at aa:bb:cc:dd:ee:ff.” These phrases are convenient summaries of the fields, not literal text strings carried inside the packet.

ARP is not TCP or UDP. It is carried directly in an Ethernet frame using its own EtherType. It has no TCP port number. This matters when writing firewall rules or interpreting packet captures: searching for a port such as 80 or 443 will not reveal ARP exchanges.

5. ARP cache: why devices remember mappings

Without caching, a host would need to broadcast an ARP request before sending every packet to a local destination. That would create unnecessary traffic and add delay. Operating systems therefore maintain an ARP cache, also called a neighbour table in some tools and documentation.

A cache entry associates an IPv4 address with a link-layer address and includes state or age information. Dynamic entries are learned through protocol activity and expire or become stale according to the operating system's behaviour. Static entries are manually configured and generally do not age in the same way, but they create administrative overhead and must be updated when hardware changes.

Cache behaviour differs among operating systems. Some systems mark entries reachable, stale, delay or probe; others expose simpler states. A stale entry does not always mean the mapping is unusable. The host may attempt to confirm reachability before replacing or deleting it.

Cache timeouts are implementation details, not a universal fixed value. They may vary by platform, kernel version, traffic patterns and network state. Do not assume every ARP entry disappears after the same number of minutes on Windows, Linux, macOS or network appliances.

When troubleshooting, inspect the entry and compare it with the expected MAC address from a trusted source. A mapping changing can be legitimate during failover, virtual machine movement, NIC replacement or gateway redundancy events. It can also be a sign of ARP spoofing. Context and repeated observations matter.

6. What happens when the destination is outside your subnet?

Suppose the same laptop at 192.168.1.20/24 wants to contact 203.0.113.40. Its subnet calculation shows that this destination is not local. The host consults its routing table and selects a default route through a gateway such as 192.168.1.1.

The laptop checks its ARP cache for 192.168.1.1. If no valid mapping exists, it broadcasts an ARP request asking for the gateway's MAC address. The router replies with the MAC address of its LAN interface. The laptop then sends an Ethernet frame to that MAC address, while the IP packet inside still has 203.0.113.40 as its destination.

The router receives the frame, removes the Layer 2 header, examines the IP packet and performs a routing lookup. It then prepares a new Layer 2 frame for the next link. On Ethernet, it may need to resolve the next-hop router or destination host on that outgoing segment using ARP as well.

This process repeats at each routed Ethernet hop where IPv4 next-hop resolution is needed. The laptop does not need to know the MAC addresses of every router along the path. It only needs the local next-hop MAC address for the frame it is currently sending.

This is why a successful ARP lookup for the default gateway does not prove that the remote internet destination is reachable. It proves only that the host has a local Layer 2 mapping for the gateway. Routing, DNS, firewall policy, upstream connectivity and the destination service can still fail.

7. Gratuitous ARP and address conflict detection

Gratuitous ARP is a term commonly used for ARP announcements sent by a device about its own IPv4 address, rather than only as a direct response to a request. Such announcements can update neighbour caches and help other devices notice an address change or duplicate address condition.

IPv4 Address Conflict Detection is described in RFC 5227. A host can probe an address before using it and announce its use after configuration. This helps detect another device already using the same IPv4 address on the link.

Gratuitous ARP can also be used during gateway redundancy or failover. When a virtual IP moves to a backup router, announcements can help switches and hosts update relevant forwarding or neighbour information. The exact behaviour depends on the redundancy protocol and platform.

Unsolicited ARP traffic is not automatically malicious. Network teams should understand normal address assignment, failover and virtualisation behaviour before treating every unsolicited reply as an attack. Unexpected changes, conflicting mappings and repeated announcements from unknown devices deserve investigation.

8. Proxy ARP: when a router answers for another address

Proxy ARP allows a router or another device to answer an ARP request on behalf of a different IP address when it has a route or configured reason to represent that destination. The requester receives the proxy device's MAC address and sends the frame to it. The proxy then forwards the packet toward the actual destination.

Proxy ARP has been used to connect networks or support designs where hosts do not have the expected subnet or routing configuration. It can make communication work without changing host settings, but it may hide topology problems and make traffic paths less obvious.

It should be used deliberately. Broad or unexpected proxy ARP behaviour can create confusing reachability, security and troubleshooting issues. Administrators should document which interfaces answer on behalf of which destinations and confirm that routing and access policies remain correct.

Proxy ARP is not the same as a normal ARP reply from the destination host. The responding MAC belongs to the proxy device, which is taking responsibility for forwarding traffic. Packet captures and router configuration can help identify this behaviour.

9. ARP spoofing and cache poisoning

ARP itself does not authenticate the ownership of an IPv4 address. On a typical LAN, a host may accept ARP information that claims a particular IP address is associated with a particular MAC address. An attacker who can transmit on the same Layer 2 segment may exploit this trust to send forged ARP messages and poison neighbour caches.

In a common man-in-the-middle scenario, an attacker sends forged information to a victim claiming that the default gateway's IP address maps to the attacker's MAC address. The attacker may also send forged information to the gateway claiming that the victim's IP address maps to the attacker's MAC address. If both sides accept the mappings and forwarding is arranged, traffic can pass through the attacker.

This can enable traffic observation, manipulation, denial of service or credential theft where applications lack adequate encryption and authentication. HTTPS and other end-to-end protections reduce the ability to read or alter protected application data, but they do not make ARP poisoning harmless. An attacker may still disrupt connectivity, observe metadata or target insecure protocols.

MITRE ATT&CK tracks ARP cache poisoning as technique T1557.002. Detection can include monitoring unexpected ARP replies, changes to known gateway MAC addresses, multiple IP addresses appearing to map to one unexpected MAC, and suspicious gratuitous ARP activity. Alerts need baselines to avoid false positives during legitimate failover.

10. Defences: DHCP snooping, Dynamic ARP Inspection and segmentation

Managed switches can provide controls that reduce the risk of ARP spoofing. Dynamic ARP Inspection (DAI), where supported, validates ARP packets against trusted IP-to-MAC bindings, commonly learned through DHCP snooping or configured through static inspection entries. Invalid packets can be dropped and logged.

DHCP snooping builds a binding database from DHCP exchanges on trusted interfaces. DAI can compare ARP sender information against those bindings. These features require careful switch configuration: trusted ports, static devices, servers using fixed addresses, trunk links and DHCP relay designs must be accounted for. An incomplete binding database can block legitimate devices.

Port security, 802.1X network access control, private VLANs, VLAN segmentation and physical access controls can reduce the opportunity for an untrusted device to join a sensitive Layer 2 segment. Endpoint protections and encrypted application protocols provide additional layers.

Static ARP entries can protect a small number of critical mappings in tightly controlled environments, but they do not scale well across large networks and can break during legitimate hardware changes. They should not be treated as a universal replacement for switch security features.

Network monitoring should capture ARP events at suitable points and alert on meaningful deviations. Keep an inventory of gateway MAC addresses, virtual gateway behaviour and authorised infrastructure. Combine ARP monitoring with DHCP logs, switch port information and endpoint telemetry to identify the device responsible for suspicious traffic.

11. IPv6 does not use ARP: Neighbor Discovery

ARP is used for IPv4 address resolution on Ethernet and other supported link technologies. IPv6 uses the Neighbor Discovery Protocol (NDP), which is part of ICMPv6 and is specified in the IPv6 architecture and Neighbor Discovery standards. NDP uses messages such as Neighbor Solicitation and Neighbor Advertisement to discover link-layer addresses and perform related functions.

IPv6 Neighbor Discovery also supports router discovery, reachability detection, address resolution and duplicate address detection. It is therefore broader than a simple one-for-one ARP replacement. IPv6 multicast replaces the IPv4 LAN broadcast approach for many discovery operations.

Security considerations also differ. Secure Neighbor Discovery (SEND) was designed to add cryptographic protection to some NDP functions, but deployment and support vary. Layer 2 protections such as RA Guard and switch controls can also help defend against rogue router advertisements and related attacks.

Do not troubleshoot IPv6 neighbour resolution with an IPv4 ARP table command alone. Use the platform's IPv6 neighbour tools and inspect ICMPv6 Neighbor Solicitation and Advertisement traffic in a packet capture.

12. ARP troubleshooting on Windows, Linux and network devices

Begin by identifying the local interface, IPv4 address, subnet prefix and default gateway. Confirm the intended destination is on-link or routed. Then inspect the neighbour table and compare the relevant MAC address with a trusted baseline.

Windows

Use arp -a to display the ARP cache. Microsoft documents options to add, delete and display entries. PowerShell also provides neighbour-table inspection through networking cmdlets. If a mapping appears incorrect, record it before clearing anything; repeated changes may indicate a conflict or security issue.

Linux

Use ip neigh show to inspect IPv4 and IPv6 neighbour entries. The older arp command may be available but is deprecated on many distributions in favour of the iproute2 tools. States such as REACHABLE, STALE, DELAY, PROBE and FAILED describe neighbour reachability handling.

macOS

Use arp -a to view entries. The arp utility can also display or remove mappings. Interface names and system behaviour can vary by macOS release.

Switches and routers

Network devices maintain their own ARP or neighbour tables, separate from the endpoint's cache. A router's ARP table maps next-hop IPv4 addresses to local link-layer addresses on its interfaces. A Layer 2 switch's MAC address table is different: it maps MAC addresses to switch ports and VLANs. Do not confuse these two tables.

Useful packet-capture filters include ARP traffic, and Wireshark can decode request/reply fields. Check whether requests are sent, whether replies return, whether the sender mapping changes unexpectedly and whether the switch learns the expected source MAC on the expected port.

13. Common ARP problems and what they mean

“Destination host unreachable” after an ARP request: the host may be unable to resolve the local destination or gateway. Check subnet configuration, VLAN membership, cabling, Wi-Fi association, switch port state and whether the target is powered on.

Repeated ARP requests with no reply: confirm the target IP is correct and on the local subnet. Check for duplicate IP addresses, wrong VLANs, wireless client isolation, port security, DAI drops and device firewall or sleep behaviour. A packet capture at both ends can show where the request or reply disappears.

Intermittent connection after an IP address change: stale neighbour information may persist temporarily. Check DHCP lease events, duplicate addressing, gratuitous ARP announcements and whether a virtual IP has moved to a new device.

Two devices claim the same IP: inspect DHCP reservations, static assignments and address-management records. Use conflict detection and switch-port tracing to identify both devices before changing configuration.

Internet access fails but gateway ARP works: local address resolution is probably functioning. Continue with routing, DNS, firewall, WAN and remote-service tests rather than repeatedly clearing the ARP cache.

Unexpected MAC address for the gateway: compare with the known router or virtual gateway address, check failover events and inspect switch port and ARP traffic. If the change is not explained, investigate possible spoofing or an unauthorised device.

14. ARP, switches, routers and VLANs: how they fit together

ARP, MAC learning and IP routing are related but separate processes. A switch learns source MAC addresses from Ethernet frames and records which port and VLAN can reach each MAC. When it receives a unicast frame, it consults that MAC table to decide where to forward it. If the destination MAC is unknown, it may flood the frame within the VLAN.

ARP resolves an IPv4 address to a MAC address. A host uses the result to build the destination Ethernet frame. The switch then uses its MAC address table to forward that frame at Layer 2. A router receives frames addressed to its interface MAC, processes the IP packet and routes it toward the next network.

VLANs create separate Layer 2 broadcast domains. An ARP request in one VLAN is not normally delivered into another VLAN. If devices in different VLANs need to communicate, a Layer 3 routing function is required. Each VLAN/subnet has its own local neighbour-resolution context.

This layered view is useful for troubleshooting. If an ARP request is visible on one VLAN but the target is in another, the host's subnet mask or gateway configuration may be wrong. If the ARP reply is correct but the frame does not reach the expected port, inspect switch MAC learning, VLAN tagging and spanning-tree state.

15. ARP cache commands: safe operational habits

Commands that display the ARP cache are useful diagnostics, but clearing entries should not be the first response to every connectivity issue. A cache flush can temporarily force new broadcasts and may interrupt active communication while mappings are relearned. It can also erase evidence useful for identifying a spoofing event.

Record the affected IP address, MAC address, interface, timestamp and state before modifying entries. Compare the result with the gateway's interface configuration, DHCP lease information, switch MAC table and asset inventory. If a mapping changes repeatedly, capture traffic to understand which device is advertising it.

Use static entries only when there is a documented operational reason and a process to maintain them. In dynamic networks with redundant gateways, virtual machines or frequently replaced devices, static mappings can become stale and cause outages.

Follow your organisation's change process before modifying network-device configuration. On production networks, coordinate with the network owner and ensure rollback access is available. A simple ARP cache deletion is usually low risk on a single endpoint, but a switch security-policy change can affect an entire VLAN.

16. What ARP cannot do

ARP does not resolve hostnames to IP addresses; DNS does that. ARP does not assign IP addresses; DHCP or manual configuration does that. ARP does not choose a route; the host or router routing table does that. ARP does not discover remote MAC addresses across routers, and it does not authenticate the claimed owner of an IPv4 address.

ARP is also not a general-purpose internet protocol for all IP versions. IPv6 uses Neighbor Discovery. Nor does ARP provide encryption, user authentication or application-level access control. A valid ARP mapping only tells the sender which local MAC address it currently believes corresponds to a next-hop IPv4 address.

These boundaries are important because troubleshooting often goes wrong when one protocol is expected to solve another layer's problem. A laptop may have a correct ARP entry and still fail to resolve DNS. It may reach its gateway but have no internet route. It may have a correct route but be blocked by a firewall. Diagnose each layer independently.

Conclusion: ARP connects local IP delivery to Ethernet forwarding

ARP bridges IPv4 addressing and local link-layer delivery. A host checks whether a destination is local, chooses either the destination or a router as its next hop, resolves that next hop's MAC address and sends an Ethernet frame. Caches avoid repeated broadcasts, while gratuitous ARP and address-conflict detection support changes and duplicate detection.

Because classic ARP does not authenticate mappings, a device on the same Layer 2 segment may attempt spoofing or cache poisoning. Switch protections such as DHCP snooping and Dynamic ARP Inspection, segmentation, monitoring and end-to-end encryption reduce risk when correctly designed.

For reliable troubleshooting, separate the routing table, ARP neighbour table and switch MAC address table. Each answers a different question. Understanding those roles makes it easier to identify whether a failure is caused by addressing, local delivery, VLAN configuration, routing or a security control.

Frequently asked questions about ARP

1. What is ARP in networking?

ARP (Address Resolution Protocol) maps an IPv4 address to a link-layer address, such as an Ethernet MAC address, on the local network. It lets a host construct the Ethernet frame needed to deliver an IPv4 packet to its local destination or next-hop router.

2. Does ARP find the MAC address of a website?

Usually no. For a remote website, a host sends the frame to its local default gateway. It resolves the gateway's MAC address, not the remote web server's MAC address, because routers separate Layer 2 broadcast domains.

3. What is an ARP request?

An ARP request asks which device owns a particular IPv4 address. On Ethernet it is normally sent as a broadcast frame so devices in the local VLAN can inspect it. The device using the target address can respond with an ARP reply.

4. What is an ARP reply?

An ARP reply provides the mapping between an IPv4 address and a hardware address. In common Ethernet IPv4 operation, the target device sends its MAC address to the requester, often using a unicast Ethernet frame.

5. What is an ARP cache?

An ARP cache stores recently learned IP-to-MAC mappings so a host does not need to broadcast a new ARP request for every packet. Entries can be dynamic or static and have platform-specific states and ageing behaviour.

6. What is gratuitous ARP?

Gratuitous ARP is an unsolicited ARP announcement about a device's own IPv4 address. It can help update neighbour information, announce a failover or detect an address conflict, but unexpected announcements can also warrant investigation.

7. What is ARP spoofing?

ARP spoofing is when a device sends forged ARP messages to associate an IP address, often a gateway, with an attacker-controlled MAC address. This can redirect traffic, enable interception or cause denial of service on a local network.

8. How can ARP spoofing be prevented?

Controls include Dynamic ARP Inspection with DHCP snooping, network segmentation, port security, 802.1X, trusted static bindings for selected systems, monitoring and encrypted application protocols. The right combination depends on the switch, endpoint and network design.

9. Does IPv6 use ARP?

No. IPv6 uses Neighbor Discovery Protocol (NDP), carried in ICMPv6, for address resolution and related functions such as router discovery and duplicate address detection.

10. What is the difference between an ARP table and a MAC address table?

An ARP table maps IPv4 addresses to MAC addresses. A switch MAC address table maps MAC addresses to switch ports and VLANs. Hosts and routers use ARP for next-hop resolution; Ethernet switches use MAC tables for Layer 2 forwarding.
